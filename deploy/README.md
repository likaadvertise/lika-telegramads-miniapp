# راه‌اندازی سرور Lika Ads

راهنمای کامل، از سرور خالی تا رباتِ کارکننده.

---

## قبل از شروع، سه نکتهٔ مهم

**۱. سرور باید خارج از ایران باشد.**
سرور برای کار کردن باید بتواند به `api.telegram.org` وصل شود. سرورهای داخل ایران
معمولاً به این آدرس دسترسی ندارند. پس سرور خارج بگیرید (خیلی از شرکت‌های ایرانی
سرور خارج با پرداخت ریالی می‌فروشند).

**۲. یک توکن گیت‌هاب لازم است.**
مخزن خصوصی است، پس سرور بدون اجازه نمی‌تواند کد را بردارد. یک توکن فقط-خواندنی
بسازید — پنج دقیقه کار است:

1. به [github.com/settings/personal-access-tokens](https://github.com/settings/personal-access-tokens) بروید
2. **Generate new token** را بزنید
3. یک اسم بگذارید، مثلاً `lika-server`
4. در **Repository access** گزینهٔ **Only select repositories** و مخزن
   `lika-telegramads-miniapp` را انتخاب کنید
5. در **Permissions → Repository permissions**، فقط **Contents** را روی
   **Read-only** بگذارید و بقیه را دست نزنید
6. توکن ساخته‌شده را کپی کنید و جایی امن نگه دارید — گیت‌هاب فقط یک‌بار نشانش می‌دهد

> این توکن فقط اجازهٔ خواندن همین یک مخزن را دارد؛ نه می‌تواند چیزی تغییر دهد
> و نه به مخزن‌های دیگرتان دسترسی دارد.

**۳. یک دامنه یا زیردامنه لازم است.**
تلگرام فقط آدرس `https` معتبر را باز می‌کند. اگر دامنه ندارید، رایگان‌ترین راه:
از سرویس `sslip.io` استفاده کنید. اگر آی‌پی سرورتان `5.6.7.8` است، این آدرس
بدون هیچ ثبت‌نامی کار می‌کند:

```
5-6-7-8.sslip.io
```

## مشخصات سرور

کمترین چیزی که کافی است:

| مورد | مقدار |
|---|---|

| رم | ۱ گیگابایت |

## نصب (یک دستور)

بعد از خرید سرور، شرکت یک آی‌پی و رمز root به شما می‌دهد. با برنامهٔ SSH
(در ویندوز: PowerShell یا PuTTY) وصل شوید:

```bash
ssh root@آی‌پی‌سرور
```

بعد این سه خط را کپی و اجرا کنید. در خط اول، به‌جای `توکن_گیت‌هاب_شما`
همان توکنی را بگذارید که بالاتر ساختید:

```bash
export GH_TOKEN=توکن_گیت‌هاب_شما
curl -fsSL -H "Authorization: Bearer $GH_TOKEN" https://raw.githubusercontent.com/likanetworkservice-oss/lika-telegramads-miniapp/main/deploy/setup.sh -o setup.sh
bash setup.sh
```

> چرا خط اول لازم است؟ چون مخزن خصوصی است، حتی برای برداشتنِ خودِ فایل نصب
> هم باید توکن را نشان دهیم. با `export`، اسکریپت هم آن را می‌بیند و
> دیگر دوباره نمی‌پرسد.

اسکریپت چهار چیز از شما می‌پرسد:

1. **دامنه** — مثلاً `ads.lika.com` یا `5-6-7-8.sslip.io`
2. **توکن ربات** — از BotFather (هنگام تایپ روی صفحه دیده نمی‌شود)
3. **شناسهٔ عددی شما** — از [@userinfobot](https://t.me/userinfobot)
4. **شناسهٔ چت سفارش‌ها** — اگر خالی بگذارید، خودتان در نظر گرفته می‌شوید

و بعد خودش همه‌چیز را نصب می‌کند: Node.js، گواهی https، سرویس دائمی.

> اسکریپت کد را از شاخهٔ `main` برمی‌دارد. پس قبل از اجرا مطمئن شوید کد
> در گیت‌هاب روی شاخهٔ `main` هست.

> اگر دامنهٔ واقعی دارید، قبل از اجرا یک رکورد `A` بسازید که به آی‌پی سرور اشاره کند.
> با `sslip.io` نیازی به این کار نیست.

---

## بعد از نصب

اسکریپت آدرس نهایی را نشان می‌دهد. دو کار باقی می‌ماند:

**۱. وصل کردن مینی‌اپ به ربات** — در BotFather:
```
/setmenubutton
```
ربات را انتخاب کنید، آدرس را بدهید، و برای متن دکمه بنویسید: `پنل تبلیغات`

**۲. تست** — در ربات خودتان `/start` بزنید. باید پیام خوش‌آمد و دکمه‌ها بیایند.

سپس یک سفارش آزمایشی ثبت کنید؛ باید بلافاصله در چت شما پیام سفارش با
دکمه‌های تغییر وضعیت بیاید.

## دستورهای روزمره

| کار | دستور |
|---|---|
| دیدن لاگ زنده | `journalctl -u lika-ads -f` |
| وضعیت سرویس | `systemctl status lika-ads` |
| راه‌اندازی مجدد | `systemctl restart lika-ads` |
| به‌روزرسانی کد | `bash /opt/lika-ads/deploy/update.sh` |
| تغییر تنظیمات | `nano /opt/lika-ads/server/.env` سپس راه‌اندازی مجدد |

---

## پشتیبان‌گیری

کل دیتابیس یک فایل است:

```
/opt/lika-ads/server/data/lika.db
```

برای گرفتن نسخهٔ پشتیبان روی کامپیوتر خودتان:

```bash
scp root@آی‌پی‌سرور:/opt/lika-ads/server/data/lika.db ./backup-lika.db
```

پیشنهاد می‌شود هفته‌ای یک‌بار این کار را انجام دهید.

## اگر مشکلی پیش آمد

**سرویس بالا نمی‌آید:**
```bash
journalctl -u lika-ads -n 40 --no-pager
```
معمولاً یعنی `BOT_TOKEN` اشتباه است یا سرور به تلگرام دسترسی ندارد.

**آیا سرور به تلگرام وصل می‌شود؟**
```bash
curl -s https://api.telegram.org
```
اگر جواب نداد، سرور شما به تلگرام دسترسی ندارد (احتمالاً داخل ایران است).

**گواهی https گرفته نشد:**
```bash
journalctl -u caddy -n 30 --no-pager
```
معمولاً یعنی دامنه هنوز به آی‌پی سرور اشاره نمی‌کند، یا پورت‌های ۸۰ و ۴۴۳ بسته‌اند.

**کد پروژه برداشته نمی‌شود (خطای Authentication یا 404):**
یعنی توکن گیت‌هاب اشتباه است، منقضی شده، یا اجازهٔ خواندن این مخزن را ندارد.
یک توکن تازه بسازید و دوباره `setup.sh` را اجرا کنید. اگر خطا دربارهٔ شاخه بود،
یعنی کد هنوز روی شاخهٔ `main` نیست.

**توکن گیت‌هاب را عوض کردم:**
فایل زیر را با توکن تازه به‌روز کنید (فقط همین یک خط داخلش است):
```bash
nano /etc/lika-ads/git-credentials
```
شکل خط باید این باشد: `https://x-access-token:توکن@github.com`

**ربات جواب نمی‌دهد ولی سرویس روشن است:**
مطمئن شوید فقط یک نسخه از سرور در حال اجراست. دو نسخهٔ همزمان با روش polling
پیام‌ها را از دست هم می‌قاپند.
