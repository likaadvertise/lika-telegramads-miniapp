# تست‌های خودکار

دو دستهٔ تست که کل مسیر پروژه را بررسی می‌کنند. هیچ‌کدام به تلگرام واقعی
وصل نمی‌شوند — یک «تلگرام تقلبی» محلی بالا می‌آید و پاسخ‌ها را شبیه‌سازی می‌کند،
پس اجرایشان بی‌خطر است و توکن واقعی لازم ندارند.

| فایل | چه چیزی را بررسی می‌کند | تعداد |
|---|---|---|
| `test-server.mjs` | API، اعتبارسنجی، امنیت، ثبت‌نام، اعلان‌ها | ۵۴ |
| `test-e2e.mjs` | کل مسیر مخاطب در یک مرورگر واقعی | ۶۴ |
| `test-vercel.mjs` | همان چیزی که روی Vercel اجرا می‌شود | ۴۱ |

## اجرا

```bash
node tests/test-server.mjs
node tests/test-e2e.mjs      # به playwright نیاز دارد
```

اگر `playwright` نصب نیست:

```bash
npx playwright install chromium
```

## تست با دیتابیس Postgres

پروژه با دو دیتابیس کار می‌کند. دو تست اول به‌طور پیش‌فرض از SQLite استفاده
می‌کنند، ولی اگر `POSTGRES_URL` بدهید همان تست‌ها روی Postgres اجرا می‌شوند —
یعنی دقیقاً همان چیزی که روی Vercel بالا می‌آید:

```bash
npm install                                            # برای درایور pg
export POSTGRES_URL=postgresql://user:pass@host/dbname

node tests/test-server.mjs     # همان ۵۴ تست، این بار روی Postgres
node tests/test-e2e.mjs        # همان ۶۴ تست، این بار روی Postgres
node tests/test-vercel.mjs     # ۴۱ تست مخصوص Vercel (فقط Postgres)
```

> ⚠️ تست‌ها جدول‌های دیتابیس را **پاک می‌کنند**. هرگز `POSTGRES_URL` دیتابیس
> واقعی را به تست‌ها ندهید؛ یک دیتابیس جدا برای تست بسازید.

`test-vercel.mjs` از فایل `vercel-shim.mjs` استفاده می‌کند: یک شبیه‌ساز کوچک که
رفتار Vercel را روی همین ماشین بازسازی می‌کند (خواندن بدنهٔ درخواست، توابع
`res.status/json/send`، و مسیریابی پوشهٔ `api`). این‌طور می‌شود کد Vercel را
بدون دیپلوی واقعی تست کرد. خودِ این فایل روی Vercel اجرا نمی‌شود.

## چه چیزهایی پوشش داده شده

**سرور:** رد کردن درخواست بدون امضای تلگرام، امضای جعلی، نشست منقضی؛
اعتبارسنجی بودجه، لینک، متن، کشور و موضوع؛ جدا بودن سفارش‌های کاربران از هم؛
ثبت‌نام با کد تأیید و محدودیت‌هایش؛ شمارهٔ تکراری؛ گرفتن نام کانال از تلگرام؛
ارسال اعلان سفارش و لید به تیم؛ سرو شدن فایل‌ها و جلوگیری از خروج از پوشهٔ web.

**Vercel:** ساخته شدن جدول‌ها در Postgres، معرفی آدرس webhook به تلگرام، رد شدن
پیام‌های بدون رمز یا با رمز اشتباه، پاسخ ربات از راه webhook، ثبت‌نام و ثبت سفارش
روی Postgres، تغییر وضعیت با دکمهٔ تیم، و بررسی مستقیم اینکه داده‌ها واقعاً در
جدول‌های Postgres نشسته‌اند.

**مرورگر:** ثبت‌نام کامل با خواندن کد از پیام تلگرام، تایمر شمارش معکوس،
ویرایش نام و شماره، انتخاب نوع تبلیغ و ظاهر شدن فیلد آدرس، پیش‌نمایش با نام و
عکس واقعی کانال، ثبت سفارش و رسیدنش به دیتابیس، رفتار درست در حالت نمایشی،
و اینکه کاربر ثبت‌نام‌کرده دوباره صفحهٔ ثبت‌نام را نبیند.

> پوشهٔ `.tmp` هنگام اجرا ساخته می‌شود و دیتابیس موقت تست داخلش می‌نشیند.
